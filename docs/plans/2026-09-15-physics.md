# Rapier physics integration

Status: implemented and validated on Windows, 2026-09-15. This introduces one engine
crate, `nico-physics`, with Rapier 3D behind a small Nico-facing API. Current
architecture belongs in [architecture](../architecture.md#physics); validation
evidence belongs in [roadmap phase 5](../roadmap.md#validation-evidence).

## Decision and scope

Use `rapier3d-f64` 0.35.3 for body dynamics, collision detection, shape casts, and
character movement. The arena already uses double-precision authoritative positions.
Rapier's `enhanced-determinism` feature is enabled without parallel stepping. This
does not prove Nico's cross-platform determinism; validate that before choosing a
network synchronization model. Rapier's profiler feature is not enabled; Nico's
profiling work remains deferred.

The first integration is 3D. It exposes fixed, dynamic, and position-driven
kinematic bodies; ball, cuboid, and Y-capsule shapes; density, friction, restitution,
sensors, collision groups, poses, linear velocity, contact snapshots, and shape
casts. Each body owns one collider. Mesh colliders, joints, forces/torques, 2D physics,
serialization/rollback, and advanced controller configuration need concrete
consumers before expanding this API.

## Ownership

`PhysicsWorld` owns Rapier state and private provider handles. Its public `BodyId`
is local to that world, is not reused, and must not be transferred between worlds.
Creation is capacity-bounded. Input rejects nonfinite coordinates, invalid quaternion
units, dimensions, material values, and timesteps outside (0,1] seconds.
Pose rotations are unit quaternions in XYZW order; no Euler pose is stored.

Mutation and query calls run on the owning simulation thread.
`update_collision_geometry()` lazily copies colliders, computes their current world
poses, and builds a separate spatial tree after insertion, teleport, removal, or a
dynamics step. Lookup storage is bounded by body capacity. Refreshing this geometry
does not mutate the dynamics world or consume its pending changes. Kinematic targets
become lookup geometry only after stepping. `step` advances physics using the
supplied duration. If Rapier disables invalid simulation state, the wrapper latches
`SimulationFailed`; recreate the world after closing it. `close` releases provider
state and rejects later mutations. There are no workers or transports.

Sensors enable all body-type combinations, so fixed and kinematic triggers detect
kinematic characters. Bilateral collision-group masks still restrict detection.
Solid colliders retain Rapier's default active collision types.

The default `runtime` feature adds `PhysicsPlugin`, `PhysicsBody`, and
`PhysicsEntities`. Removing a body component or despawning its entity removes its
body/collider at the next fixed boundary. Shape/material edits replace the body and
invalidate its old ID. Dynamic results are copied into components. Kinematic pose
edits set the next motion target; other pose edits teleport.

Register input/intent plugins before physics, then result consumers after physics.
The runtime's normal registration order determines fixed-system ordering. A typed
`ContactFrame` event carries touching entity pairs after each step, including sensors;
it is an observation, not a damage or contact-start event. Contact storage is capped
at 4,096 pairs with explicit truncation. Runtime event retention remains bounded by
the existing event bus. Failed systems do not roll back direct world mutations.

## Arena migration

The arena owns a persistent physics world inside its headless simulation resource.
It synchronizes four actor slots before moving them in stable order. Dead actors
are removed; restart and wave transitions restore current gameplay positions.
The four authored walls supply cuboid colliders. Actors use 0.4-radius spheres at
a fixed height, preserving the game's circular floor footprint.

Rapier's controller calculates corrected displacement; the game applies it on XZ
and keeps its perimeter constraint. The arena disables slope climbing and ground
snapping, retains a 0.0001-unit separation margin, and does not push other actors.
Combat sectors, facing, damage, invulnerability, and timing remain game rules.
The old unused `nico-spatial` circle-slide solver is removed. Conservative camera
sphere/box queries remain in `nico-spatial` with their existing controller contract.

## Validation scope

Engine tests cover falling/resting bodies, contacts, sensors, filters, immediate
query updates, slopes, kinematic pushing, invalid input, capacity, repeated fixed
steps, component edits/removal, entity despawn, contact truncation, provider failure,
failed runtime steps, and shutdown.
Regression coverage compares complete dynamic trajectories with and without shape
casts and character movement calculations across insertion, teleport, sleep/wake,
and replacement. Sensor entry/exit tests cover fixed and kinematic triggers,
creation order, masks, and runtime contact events.
The bounded `falling_box` example demonstrates ECS/runtime composition.
Arena tests and native MCP automation exercise real movement, combat, wave resets,
victory/defeat, and shutdown through the migrated implementation.
