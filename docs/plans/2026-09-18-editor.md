# Integrated editor and watched imports

Status: initial editor implemented. Windows native validation and automated checks
are recorded in [roadmap phase 8](../roadmap.md#8-make-development-repeatable).

## Outcome

An `apps/nico-editor` desktop application uses egui with a live Nico viewport,
an asset browser, scene hierarchy, and property editing. A project can place GLB
models, edit transforms, save a scene, and reopen it. PNG assets have an inspection
preview. Editor dependencies do not enter shipped game packages.

## Import ownership

`nico-assets` owns an optional watched project catalog. Source PNG/GLB files are
authoritative. Native file notifications request debounced reconciliation; stat
checks remain the fast path, with periodic reconciliation recovering missed events.
Access-only notifications and generated cache files do not trigger imports.
The existing versioned import cache is reused, including its validation and budgets.
Imports run on a bounded worker, and consumers adopt immutable successful results at
their owned update boundary. Failed or deleted sources report an error while keeping
the last successful value. Startup discovers existing files. Creation, modification,
rename, deletion, and atomic-save replacement are reconciled.

## Editor ownership

The editor owns the document, selection, undo/redo, and project-relative asset paths.
The embedded headless runtime owns the preview world. Engine rendering supplies the
viewport through a provider integration; egui does not enter runtime or presentation
contracts. UI and bridge commands use the same bounded edit operations. Existing host
status, diagnostics, and stop names are preserved; bridge disconnect leaves the
editor running. Saved scene data is separate from derived import cache data.

## Acceptance

- Build and run the integrated editor with a rendered, resizable scene viewport.
- Discover PNG/GLB sources and observe actual native file notifications.
- Verify unchanged stat checks avoid imports, edits update previews, invalid edits
  preserve last-good data, and deletion/recreation recovers.
- Place and transform a model, undo/redo, save, and reopen the scene.
- Verify bounded queues, worker shutdown, stale-result handling, and import failures.
- Exercise discoverable editor operations through nico-bridge and inspect captures
  from the same editor instance. Record rendering separately from user observation.
- Run relevant unit/integration tests, workspace checks, formatting, and Clippy;
  document tested platform and remaining limitations.

Full terrain tooling, graph editors, game-code hot reload, advanced material authoring,
and automatic scene merging are future extensions, not part of this first editor.

## Project integration update (2026-09-18)

The [project-scene plan](2026-09-18-project-scenes.md) extends this initial design
with manifests and a game consumer. Scene serialization is now engine-owned in
`nico-scene`; editor history remains application-owned. Manifest projects use their
declared asset roots and default scene; loose content directories remain supported.

## Startup and navigation update (2026-09-18)

Project loading now starts after the first presented shell frame, on a joined worker.
The loading dialog shows import phases/counts and the asset currently being decoded.
The catalog publishes discovery and each completed import separately, so the folder
tree can display queued files immediately. Source filtering retains ancestor folders.
Left-drag horizontal orbit direction is corrected. Middle-drag and Shift+left-drag
pan in the camera plane; selecting an object clears the pan offset. The same offset
is available through the queued MCP `pan` command. UI pointer-event regressions
exercise all three gestures, not just their transform math.
